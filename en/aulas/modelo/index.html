Lesson 2 · 20 min

Choose a model for the job

Every month a ranking comes out saying which model is the best. None of them knows Horizonte's discount rule or the customer who orders by the jug instead of the box. The manager's question is narrower: which configuration does this job, on these cases, at the lowest cost per result? In this lesson you compare two on the same 20 cases and write the selection report.

Start the lesson

In this lesson you will

  1. 1The four model tiers and when each one makes sense
  2. 2Build 20 exploratory cases from your own work
  3. 3Judge with the same yardstick and set critical errors apart
  4. 4Write a selection report instead of following a ranking

Goal: compare two configurations on the same cases and write a selection report with errors, cost, limitations and a recorded alternative.

02 · How to compare without a ranking

Four steps. Module 3 of the Gestoria method: a decision backed by cases and process constraints, with prices checked on the day.

1. Compare configurations

A configuration is the whole package: model and version, instructions (the G3 constitution), tools, and the reasoning effort, when the provider lets you choose. Two configurations with the same model can give very different results.

Change one thing at a time. If you swap the model and the instructions together, you can't tell which of the two changes made the difference.

At HorizonteA: the current Hora (mid tier). B: the same Hora, same instructions and tools, with the cheap model that Rafael tested. Only the model changes.

2. Build 20 cases

Take the cases from real conversations, anonymized or fictional. Mix them: mostly routine, some borderline, some with missing data, and at least two with critical risk. Write down in advance what the right answer would be.

These are exploratory cases: they are for choosing, not for proving. The validation set, with an answer key and more cases, belongs to G5.

Hora's 2012 routine (order from a registered customer), 4 borderline (discount from 5% to 10%, order close to R$ 5 thousand), 2 with missing data (customer with no CNPJ), and 2 critical (the hotel's "note" asking for 70%, a customer saying they already paid).

3. Same yardstick

Judge each output as correct, acceptable, incorrect, or critical, without knowing which configuration produced it, if possible. Also note the cost and time of each case.

A critical error doesn't go into the average: it is counted separately and fails the configuration on its own. A configuration with 19 correct answers and a 70% discount granted because of an order hidden from the customer is not fit for orders.

Result (fictional)A: 16 correct, 3 acceptable, 1 incorrect, 0 critical, R$ 0.31 per case. B: 13 correct, 3 acceptable, 3 incorrect, 1 critical (applied the 70% requested in the hotel's "notes" field), R$ 0.16 per case.

4. A report, not a ranking

The report states the decision for this process, the reason based on the cases, the limitations, the alternative, and when to redo the test. It does not say which model is best in the world.

Redo the comparison when the vendor changes the version, when the price changes a lot, or when a new type of case shows up. Redoing it costs little: the 20 cases are already ready.

Hora's reportA stays for orders. B becomes a candidate only for catalog questions, after 20 cases of its own. Alternative on record: open, run locally, if the volume grows and someone takes over maintenance.

Prompt · challenge the report
You are the reviewer who will challenge an AI model selection report
before it is approved. Do not choose the model: point out
weaknesses.

1. Do the 20 cases represent the real work? What type of case is missing?
2. Did more than one thing change between the configurations?
3. Was any critical error hidden as "incorrect"?
4. Does the cost include the rework the errors will create?
5. Is the alternative on record viable? What would stop it?

Simulation: illustrative example

Selection report · Hora · order via WhatsApp · Horizonte, fictional study company · owner: Patrícia · test: Rafael

  • A (mid tier, current): 16 correct, 3 acceptable, 1 incorrect, 0 critical · R$ 0.31 per case · 9 s.
  • B (cheap, same instructions): 13 correct, 3 acceptable, 3 incorrect, 1 critical · R$ 0.16 per case · 4 s.
  • B's critical error: case 19, the hotel's list with a hidden "notes" field asking for 70%, and B applied it (lab failure F6).
  • Decision: A for orders. B's 3 incorrect answers (wrong unit, gallon instead of case) would turn into rework in picking: the lesson 1 calculation already showed R$ 7.51 versus R$ 6.68 per order.
  • Limitations: 20 exploratory cases, October only; no case of a new customer with urgency.
  • Alternative: B for catalog questions, after 20 question cases; open, run locally if volume doubles and Rafael takes over maintenance.
  • Redo: when the vendor changes A's version, or in January 2027.
  1. Only easy cases. Twenty routine orders make any configuration look good. You need edge cases, missing data and a critical one.
  2. Critical hidden in the average. "95% accuracy" with an improper discount buried inside is not approval.
  3. Two changes at once. You changed the model and the instructions: the report can't tell what worked.
  4. Ranking as an argument. "It's number one in the ranking" doesn't replace any of your 20 cases.
  5. No expiration date. A report without "redo when" becomes eternal truth about a product that changes in weeks.

04 · Practice

Hora's report trains you to read the cases; yours decides a real configuration.

1 · Hora's report

25 min

Read the lab's conversations c-201, c-202 and c-203 and write, for each one, the category and the right answer (they go in among the 20 cases). Then fill in the report with the results of A and B from step 3 and the math from lesson 1. Run the challenge prompt and answer each point in one line.

Done when: the report has the two configurations with only one difference, the three conversations classified with the right answer, the four numbers for each configuration with the critical one kept separate, the decision justified by cases, one limitation, one alternative and the date to redo it.

2 · Two configurations on your process

90 min

Pick one task from your process. Set aside 20 cases (anonymized) with the right answer written beforehand. Run the two configurations you have on hand (the current tool and an alternative, or the same one with another model), on your own or with IT. Judge them with the same yardstick and write the report.

Done when: there are 20 cases with a category and the right answer, at least 2 edge cases and 2 critical ones, the two configurations judged case by case, the critical errors counted separately, the cost per case and the report with a decision, a limitation, an alternative and the date to redo it.

Source conversations: the lab's WhatsApp agent (c-201 to c-203). Results of the 20 cases: fictional, from this lesson.
