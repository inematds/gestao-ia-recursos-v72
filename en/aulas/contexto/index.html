Lesson 3 · 20 min

Company knowledge as an asset

On Monday morning, Hora quoted the detergent at September's price. It wasn't the model's mistake: the new price table and the old one were in the same folder, and nobody owned either one. The agent knows what the company wrote for it. In this lesson you organize that knowledge as an asset: each document with an owner, a version and an expiry date.

Start the lesson

In this lesson you will

  1. 1The five types of knowledge the agent reads
  2. 2Owner, version and expiry date on every document
  3. 3Resolve conflicts between sources before the agent picks one
  4. 4What stays out of the package, and why an example is not a test

Goal: organize the procedures, examples and rules the agent reads into a context package where each document has an owner, a version and an expiry date.

02 · How to turn documents into an asset

Four rules. None requires programming; all require deciding who takes care of what.

1. Every document has an owner

For each document: owner (who fixes it when it is wrong), version, expiration date and where it lives. "The company" or "sales" is not an owner: when nobody is, nobody updates it.

The owner tells whoever looks after the agent when the document changes. If the table changes, the version the agent uses changes the same day, and the previous one goes to the archive.

At Horizonte (fictional)The September price went out because the folder had "tabela-precos.pdf" and "tabela-precos-NOVA.pdf". Now: "Price table · v2026-10 · valid until 10/31 · owner: Patrícia". Only one in use.

2. Resolve conflicts beforehand

If two documents disagree, the agent picks one, and you only find out when a customer complains. Write the order of precedence: rules outrank reference, which outranks procedures, which outrank examples.

If it finds a conflict, the agent does not decide: it passes the case along and the document's owner fixes it. A conflict found is a task with an owner and a deadline, not a footnote.

A real conflict in the packageThe delivery FAQ said "minimum order of 5 boxes"; the October commercial policy lowered it to 3. The policy wins. Juliana, the FAQ's owner, fixes it by Friday.

3. Reusable procedure

A procedure is the team's experience written in a way that another person, or the agent, can repeat. It has a trigger (when to use it), when not to use it, required inputs, steps you can check, and an output with a defined format.

Test the procedure with a new person before the agent: if they get stuck on a step, the agent will get stuck too, only without telling you.

At Horizonte"Build a restock order": use it when a registered customer asks for items they have already bought; do not use it for a new customer. Inputs: customer, items, quantities in boxes. Output: a draft order with the price from the current table and its version.

4. An example is not a test

Examples teach; test cases measure. If the same case is in both, the measurement lies. Keep the 20 cases from lesson 2 in a folder the agent does not read.

Also define memory: what the agent keeps from one conversation to the next, for how long, and who can correct it. Legal retention periods for personal data are up to whoever handles data protection (LGPD) at the company.

Hora's memoryKeeps: items the customer usually orders and their preferred delivery day. Does not keep: Tax ID (CPF), the whole conversation, payment data. Who corrects it: Juliana, at the customer's request.

  1. Generic owner. "Sales" does not fix documents. Put a name.
  2. Two versions in use. Look for files with "new", "final", "v2-correct" in the same folder: one of them will get read.
  3. Everything inside. Putting the entire customer spreadsheet in "so the agent knows more" exposes data and makes every conversation more expensive.
  4. Test as example. If the hotel case is in the examples, its test no longer measures anything.
  5. Check: for each line of the index, open the document and see whether the owner, version and expiration date are written in it, not only in the index.

04 · Practice

Patrícia's package is for practice; the one for your area is the real thing.

1 · Patrícia's package

30 min

Open Hora's prompt in the lab and mark what in it is a rule, a reference, a procedure, or an example (it's all mixed together in one text). Build the package index with the template, write one complete procedure, and list what stays out. Put the lab's customer spreadsheet on the out list and say why.

Done when: the index has at least 6 documents, each with a type, a named owner, a version, and an expiration date; the order of precedence is written down; there is one procedure with the 9 parts of the template; the out list has at least 3 items, including the customer spreadsheet.

2 · Your area's package

60 min

List everything your process's agent reads today (or what you would hand to a new hire). Classify it, assign an owner and a version, resolve the conflicts, and write a procedure for the most frequent task. Run the conflict prompt and mark each point as fixed or as having an owner and a deadline.

Done when: the index is saved with an owner, version, and expiration date on every document, no document has two versions in use, every conflict found has an owner and a deadline, one procedure is written, and the test cases are in a folder separate from the examples.

Source materials: Hora's configuration and prompt and customer spreadsheet (what should not go into the package).
